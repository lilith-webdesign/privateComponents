# 行政审批移动端信息层级改造设计

## 目标

让行政人员先识别待办的类型与业务归属，再进入详情核对同类信息，最后始终能在拇指区完成审批。

## 列表页

- 页面主题为“行政待办”，先呈现待办总数与审批类型分类。
- 以审批类型为一级分组，例如“采购申请”“用印申请”“督办事项”；分类标题显示数量。
- 每条待办使用业务归属作辅助上下文，至少展示事项名称、业务归属、申请人、关键金额或时限，以及紧急程度。
- 类型名称和事项标题承担主要识别任务；紧急程度仅用小型状态标记，不能取代事项信息。
- 点击整条卡片进入详情，不在列表直接提供同意或驳回操作。

## 详情页

详情按业务语义分块，而非按数据来源堆叠：

1. 事项概览：审批类型、标题、申请人、业务归属、时限、紧急程度与当前状态。
2. 业务信息：按事项类型展示金额、项目、合同/用印对象等核心业务字段。
3. 审批依据：规则摘要、附件清单与缺失提示；关键依据缺失时阻止“同意”。
4. 流转记录：按时间展示提交、补充、前序意见与当前节点。

相同类别的数据不可跨块重复；长内容默认收敛，按需展开。

## 审批操作

- 详情内容区底部预留安全间距，底部审批栏固定在视窗内。
- 主按钮为“同意并提交”，次操作为“驳回”或“退回补件”。
- 驳回必须填写原因；退回补件指向需要补充的依据或字段。
- 提交后以明确的状态变更、流转记录和短提示共同反馈，避免只显示 Toast。

## 实现与验收

- 在现有行政角色场景中替换弱主次的待办展示，保持现有设计令牌和设备框架。
- 列表截图中可在不进入详情的情况下判断“是什么审批、属于什么业务、关键数据是什么”。
- 详情首屏可看到事项概览与至少一个业务信息块；所有审批操作在滚动时始终可达。
- 自动化测试覆盖新增场景文案、列表到详情切换，以及固定审批栏关键操作。
